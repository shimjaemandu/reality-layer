# v1.6 Reality Graph / State / Event Separation

## 목적

v1.5까지 Context Graph는 정적 관계, Actor의 현재 위치, Device state를 한 projection에서 함께 다뤘다. v1.6은 소유 책임을 명확하게 분리한다.

```text
Reality Graph → topology
State Store   → current mutable values
Event Store   → historical facts
Context Graph → compatibility projection
```

## Reality Graph

`src/reality-graph.js`

- spaces, actors, infrastructure, devices와 안정적인 관계를 노출한다.
- live state node를 소유하지 않는다.
- actor presence/location 같은 동적 relation을 소유하지 않는다.
- 기존 Device Graph를 compatibility source로 사용하므로 v1.5 정책 코드를 깨지 않는다.

Version: `reality-graph/1.6`

## State Store

`src/state-store.js`

현재 알려진 상태를 세 영역으로 분리한다.

- `actors`: present/location/confidence/source
- `devices`: adapter가 보고한 최신 state
- `sensors`: 최신 detected/last_event_at

Version: `reality-state/1.6`

Executor 성공 후 Device state를 동기화하고, sensor input 후 Sensor state를 동기화한다. State Store에는 역사 전체를 저장하지 않는다.

## Event Store

`src/event-store.js`

각 event는 schema, UUID, sequence, timestamp, type, source, actor, target, payload를 가진다. 최대 500개를 로컬에 보존한다.

Version: `reality-event/1.6`

현재 event type:

- `device.action.executed`
- `sensor.observation`
- `actor.presence.changed`

Event Store는 audit log와 목적이 다르다. Audit은 정책 결정과 설명 책임을 포함하는 보안 기록이고, Event Store는 Reality Context가 사용할 수 있는 시간순 세계 변화 기록이다. 향후 둘은 연결할 수 있지만 하나로 합치지 않는다.

## Context Graph compatibility projection

`src/context-graph.js`

기존 `Context Graph` API를 제거하지 않았다. 대신 Reality Graph topology와 State Store의 live values를 읽는 read-time projection으로 변경했다.

이 때문에 기존 stale-action 검증, 다른 재실자 확인, Permission/Safety 정책은 v1.5와 동일한 방식으로 계속 작동한다.

## 새 API

```text
GET /api/reality-graph
GET /api/state-store
GET /api/event-store
```

기존 API도 유지한다.

```text
GET /api/device-graph   # compatibility
GET /api/context-graph  # compatibility projection
```

## v1.7 준비

v1.7 MCP Server에서 다음 mapping을 만들 수 있다.

```text
reality.discover → Reality Graph + Capability Model
reality.observe  → State Store + selected Events
reality.plan     → Planner
reality.execute  → Policy/Safety + Executor
reality.explain  → Audit + Event history
```

v1.6의 핵심 목적은 이 인터페이스들이 같은 혼합 Graph를 서로 다른 의미로 읽지 않도록 내부 truth source를 분리하는 것이다.
