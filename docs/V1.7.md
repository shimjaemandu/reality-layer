# v1.7 Northbound MCP Server

## 목적

v1.7의 목적은 Reality Layer 내부 구현을 외부 AI에 노출하는 것이 아니라, 외부 Agent가 **Reality Layer 자체를 하나의 안전한 현실 실행 계층**으로 사용하게 만드는 것이다.

```text
Agent A ─┐
Agent B ─┼→ MCP → Reality Layer → Windows / Home / future devices
Agent C ─┘
```

AI가 바뀌어도 Reality Layer의 Human Identity, Capability, Context, Permission, Safety, State, Audit는 유지된다.

## MCP surface

```text
reality.discover
reality.observe
reality.plan
reality.execute
reality.explain
```

외부에 수백 개의 `light.turn_on`, `pc.open_app` Tool을 직접 노출하지 않는다. Reality Layer가 abstraction boundary를 유지한다.

## Modern MCP transport

v1.7은 MCP revision `2026-07-28` modern stateless lifecycle을 대상으로 한다.

```text
POST /mcp
Authorization: Bearer <token>
MCP-Protocol-Version: 2026-07-28
Mcp-Method: tools/call
Mcp-Name: reality.plan
```

`server/discover`, `tools/list`, `tools/call`을 구현한다. Tool list에는 private cache hint를 제공한다.

2025 계열 initialize/session lifecycle은 v1.7 범위에 포함하지 않는다.

## Agent identity != Reality identity

MCP `_meta`의 clientInfo는 self-reported 값이다.

```text
clientInfo.name = "owner"
```

라고 주장해도 Reality Layer Owner 권한을 얻지 못한다. clientInfo는 audit/display metadata로만 취급한다.

Human policy principal은 기존 Reality Identity가 유지한다.

## Execution boundary

`reality.execute`는 임의 Action IR을 받지 않는다. `reality.plan`이 발급한 `plan_id`만 받는다.

```text
Agent
 ↓
reality.plan
 ↓
plan_id
 ↓
reality.execute
 ↓
Stale validation
 ↓
Permission / Safety re-check
 ↓
Executor
```

따라서 Agent가 target/capability를 바꿔 Executor를 우회하는 northbound path가 없다.

## Confirmation rule

Agent는 자신의 요청을 사용자의 승인으로 간주할 수 없다.

- AUTO: MCP에서 실행 가능
- CONFIRM: MCP 실행 중단, 로컬 사용자 확인 필요
- BLOCKED: 실행 불가

`reality.execute` Tool schema에는 `confirmed` 필드가 없다.

## Direct command planning

기존 v1.3 Orchestrator의 high-level template 외에도 v1.7 northbound planner는 기존 Intent Interpreter를 통해 단일 Device 명령을 Typed Action IR plan으로 만들 수 있다.

예:

```text
침실 불 켜줘
→ bedroom_light
→ capability power/write
→ Policy AUTO
→ plan_id
```

## Audit

MCP Tool 호출과 결과는 Event Store에 추가한다.

```text
mcp.tool.called
mcp.tool.result
```

client metadata는 `self-reported-unverified`로 표시한다. 실제 기기 행동은 기존 `device.action.executed` Event 및 실행 로그와 연결된다.
